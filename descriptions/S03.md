# S03: Value nodes and the computation graph

Summary: a Value wraps one number and remembers its children and its operation, so any calculation can be stored as a graph.

## What happens in each act
- Example A: the Value class (data, grad, _prev, _op, label) is mirrored on a card for node e; then L = (a*b + c)*f is built one operation at a time with a=2, b=-3, c=10, f=-2, giving e=-6, d=4 and L=-8, and a zoom shows that a child is simply an input.
- Example B: the same two operations rearranged as L2 = (a + b)*(c + f) with a=3, b=-1, c=2, f=4 give 2, 6 and 12; the graph morphs live from one shape to the other and two plus nodes now feed one times node.
- Expert corner: the graph is built while the code runs (define-by-run): a loop with n=3 makes 7 Values and with n=5 makes 11; every node keeps _prev, which is why training needs memory; rebinding c = c + Value(1.0) makes a new node and leaves the old one in the graph.

## Formulas used
- e = a * b = 2 * (-3) = -6
- d = e + c = (-6) + 10 = 4
- L = d * f = 4 * (-2) = -8
- s = a + b = 3 + (-1) = 2, t = c + f = 2 + 4 = 6, L2 = s * t = 2 * 6 = 12

## Three key takeaways
- A Value is a number plus bookkeeping: data, grad, _prev (its children) and _op (how it was made).
- The shape of the graph comes from the expression, not from the operations alone.
- The graph is created while Python runs the code, and every node keeps its children alive.

## Glossary
- Scalar: one single number.
- Value: a scalar that remembers where it came from.
- Child: an input that a node was computed from (listed in _prev).
- Computation graph: Values joined by operations.
- Drawing helper: the round operation circles are only drawn by draw_dot and are not Values.

## Two common mistakes
- Thinking the round operation circles are Values: only the rectangles are.
- Thinking that c = c + Value(1.0) changes the old node: it makes a brand new node and moves the name, while the old node stays in the graph.
