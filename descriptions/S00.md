# S00 Intro: which way should we turn each knob?

Summary: a meaningless README expression shows what micrograd can do, then a tiny network shows why we need a direction for every knob, and a roadmap previews the twelve chapters.

## What happens
- The README demo: a = -4.0 and b = 2.0 pass through add, multiply, power, relu, negate and divide, giving g = 24.7041.
- Backward gives the slopes 138.8338 for a and 645.5773 for b; a real nudge of a by 0.001 confirms the first one.
- A network with 3 inputs, 4 hidden units and 1 output has 16 knobs; turning one blindly raises the loss, another lowers it.
- Particles flow backwards along a knob line to hint that the gradient is the direction we need.
- A roadmap of twelve chapters lights up one by one, then the three-act pattern is previewed: Example A, Example B, Expert corner.

## Formulas used
- slope is approximately (g(a+h) - g(a)) / h, with h = 0.001.
- dg/da and dg/db are the gradients that backward() fills in.

## Key takeaways
- A gradient says how fast the output moves when an input is nudged.
- Backpropagation works on any expression, however silly; neural networks are just a calmer one.
- micrograd uses single numbers on purpose; real libraries use tensors only for speed.

## Glossary
- Value: a number that remembers how it was made.
- Gradient: the slope of the output with respect to one input.
- Loss: one number measuring how wrong the network is.
- Weight (knob): a number inside the network that training turns.

## Common mistakes
- Thinking the README expression means something; it is only a stress test for the engine.
- Turning knobs by trial and error; with thousands of knobs only the gradient scales.
