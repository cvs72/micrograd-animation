## Formulas used
- x1.grad = w1 (1 - o^2) = -3 * (1 - 0.7071^2) = -1.5
- grad_in = grad_out (1 - o^2) = 1 * (1 - 0.7071^2) = 0.5
- P3(x) = 0.5 (5x^3 - 3x), P3'(x) = 1.5 (5x^2 - 1), P3'(2) = 28.5
- scalar products in a layer = examples * inputs * neurons = 4 * 3 * 4 = 48

## Three key takeaways
1. PyTorch computes the same numbers as micrograd; its extra value is speed through tensors, not different maths.
2. A layer is a matrix multiply: 48 scalar multiplications that a tensor library performs as one parallel operation.
3. PyTorch stores one hand-written derivative per operation, builds the graph as the code runs and runs reverse mode, exactly like micrograd.

## Glossary
- Tensor: an n-dimensional array of numbers; its shape tells the size along each dimension.
- requires_grad: the switch that makes PyTorch track gradients for a tensor (off by default for leaf tensors, for efficiency).
- Autograd: PyTorch's automatic backpropagation, built from one forward and one backward function per operation.
- .item(): turns a one-element tensor into a plain Python number.
- float32 and float64: 32-bit and 64-bit floating-point numbers; .double() converts to 64-bit like Python floats.
- torch.autograd.Function: the class you subclass to add your own operation with a forward and a backward.

## Two common mistakes
- Forgetting requires_grad = True on a leaf tensor, so its .grad stays empty.
- Mixing float32 tensors with float64 Python numbers and then wondering why the digits differ from the micrograd result.
