Example A: what is the gradient of b = a + a, with a = 3?
Both sides add a to itself, so b is 6; the plus node reads a twice.
Before the code runs: what should a.grad be? Nudge a, b moves twice.
Same rule on both sides; the only difference is = against +=.
The plus node starts with b.grad = 1, then passes it down the first arrow.
The second arrow arrives: the left side overwrites, the right side adds.
Right: 1 + 1 = 2. Left: the first 1 is erased, so it keeps only 1. Wrong!
Gradient accumulation: shares from every path must be summed.
The lecture's bigger case: f = d * e, where a and b each feed d and e.
f starts at grad 1; the product node gives d.grad = 1 and e.grad = -6.
Now d runs first: a gets b * 1 = 3 and b gets a * 1 = -2, on both sides.
Then e runs. It sends -6 to a and b: left overwrites, right adds on top.
The buggy side lost d's share: -6 and -6 instead of -3 and -8.
Overwriting is only right when each node is used once; a shared node adds.
Example B: what if a feeds the output two, three or more times?
Three cases on one screen: b = a + a, z = a + a + a, and y = x times x.
Predict first: for z = a + a + a, what should a.grad be?
Three arrows, three shares: the real gradient is 3, the bug says 1.
Check it: nudge a by 0.001 and watch how fast the output moves.
The yellow nudge always matches the green bar, never the red one.
So the bug grows with the uses: a node used k times loses k - 1 shares.
Expert corner: the chain rule adds one term for every path.
Take the notebook graph again. Every route from f down to a is one path.
Path one goes through d and carries e times b; path two goes through e.
Same for b: one route through d, one through e, one product each.
Each path adds its share: a node's gradient is the sum over paths.
Frameworks keep adding on purpose, so you must zero grads before each step.
Here y = x times x, x = 3: the true slope is 6 each step, not 12 or 18.
Used on purpose: add the gradients of four small batches into one big one.
Their sum is 10, the gradient of the whole batch, with less memory at once.
The rule: += inside the engine, zero the grads once per optimizer step.
